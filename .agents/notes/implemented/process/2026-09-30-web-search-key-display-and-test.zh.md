# 联网搜索密钥状态与搜索探测

## 问题

联网搜索设置和模型供应商设置都使用密码输入框保存 API Key，但对已保存密钥的状态、占位提示和说明文案不一致。两类密钥属于不同配置，不能相互引用。

## 实施

- 联网搜索密钥仍由 Host 独立保存，读取时只返回配置状态，不返回密钥内容。
- 联网搜索面板对齐模型供应商设置的已保存状态提示：输入框保持空白，显示“已配置；输入新值可替换”，并说明已保存的 Key 不会显示。
- 增加一次最多返回三条结果的测试搜索。它使用当前已保存的搜索服务和 Key，经 Gateway、SDK、App Server 调用 Host 的搜索能力，不发起模型请求。
- 搜索结果只投影标题、HTTP(S) URL、摘要和发布时间；密钥不会进入响应。

## 边界

Gateway 校验关键词与响应大小；Host 从自己的联网搜索配置构造调用；Capabilities 复用现有供应商适配器。用户需先保存配置，再使用真实搜索测试；该请求可能产生搜索供应商费用。

## 验证

- `cargo fmt --all`、受影响 Rust crate 的 Clippy、`python3 scripts/line_budget.py`、前端 Lint、前端生产构建、Ruff 检查和格式检查通过。
- 未运行测试套件或发起真实 Provider 搜索。生产构建提示现有主 JS chunk 超过 500 KB。
