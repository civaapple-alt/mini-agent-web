# ADR: SDK 0.7.0 适配评审与控制面演进落地 (Alignment Review & Control Plane Evolution)

* **日期**: 2026-09-03
* **状态**: Implemented
* **范围**: 全栈 (`mini_agent` SDK / `server` Gateway / `frontend` Web Studio / `tui` / `cookbook`)
* **上下文**: 对齐 Mini Agent App Server 0.7.0（Codex 对齐架构），对首期适配进行系统性架构评审，并落地解决运行时线程绑定、内置工具选择器（Builtin Tools Selector）、全量 `ThreadItem` 生命周期流规约以及多会话控制路由等演进需求。

---

## 1. 背景与演进动因 (Context & Motivation)

Mini Agent App Server 在 0.7.0 版本对协议与执行模型进行了深度重构，全面向 OpenAI Codex 架构标准靠拢：
1. **工具模型收敛**：内置工具裁剪为受控的 6 种标准基础工具（`read_file`, `write_file`, `edit_file`, `shell`, `web_fetch`, `read_image`），废弃非受控进程与 `read_tool_result`，确立 `Thread` → `Turn` → `ThreadItem` 三层投影；
2. **命令式工作流退役**：废弃 `workflow/plan/set` 以及手工推进的 `workflow/goal/start|pause|fail|advance` 接口；
3. **声明式控制面与自驱 Goal Runtime**：引入 `thread/settings/update` 统一声明协作模式（`collaborationMode`，如只读 `plan`）与可选的内置工具过滤列表（`builtinTools`）；Goal 推进收敛为 App Server 内部 Actor 自治的 `GoalRuntime`（API 简化为 `thread/goal/set|get|clear`）。

在初步完成 0.7.0 接口对齐后，团队针对跨端协同与运行时边界进行了全面审查，发现并梳理出以下关键问题与演进空间：
- **运行时线程绑定（Runtime Thread Binding）限制**：App Server 的 `GoalRuntime` 和 `thread/settings/update` 属于单进程内部 Actor，强绑定于启动时的运行时线程（默认 `default`）。客户端（TUI/Cookbook/Web）在切换历史会话时若直接下发设置，会因线程不匹配引发报错；
- **Goal 重入幂等性与时序竞态**：若未清空遗留 Goal，App Server 重启时会触发自动续轮，阻塞后续的 `thread/start`；
- **控制平面暴露不足**：底层已支持 `builtinTools` 过滤，但前端 Web Studio 仅提供了 Plan Mode 开关，缺乏对 6 种基础工具的可视化多选面板；
- **`ThreadItem` 投影消费不完全**：前端原先仅针对 `toolCall` 进行去重合并，对于 `contextCompaction`（上下文压缩指示）与 `reasoning`（思考链同步）仍依赖脆弱的增量拼接。

## 2. 架构决策与设计 (Architectural Decisions)

### 2.1 决策 1：解耦“会话历史线程”与“运行时控制线程”
- **机制**：在客户端状态机（TUI `TUIState`、Web 前端与 Cookbook）中，将用户正在查看/切换的会话历史线程与承载底层执行控制的 `runtime_thread_id` 显式解耦；
- **效果**：用户自由切换会话历史进行翻阅或分叉，而 `/plan`、`/goal`、`/profile` 调用始终针对绑定的 `runtime_thread_id` 下发，彻底消除了跨线程配置漂移与非法调用。

### 2.2 决策 2：内置工具选择器（Builtin Tools Selector）全栈闭环
- **后端网关**：在 `server/routes/world.py` 中锚定 6 种标准内置工具集合：
  ```python
  ALL_BUILTIN_TOOLS = [
      "read_file",
      "write_file",
      "edit_file",
      "shell",
      "web_fetch",
      "read_image",
  ]
  ```
  扩展 `UpdateThreadSettingsRequest` 与 `GET /api/workflows/state`，返回 `available_builtin_tools` 与当前生效的 `builtin_tools`；
- **Web Studio UI**：在 `SidePanel.jsx` 中新增内置工具选择卡片网格，提供 6 种工具的独立动态开关，反选即可实时剥离对应能力，遵循最小权限安全原则。

### 2.3 决策 3：全量 `ThreadItem` 生命周期驱动流规约器
- **增量 Delta 与结构化投影协同**：在 `frontend/src/utils/messageState.js` 中新增 `mergeProjectedCompactionItems` 与 `mergeProjectedReasoningItems`；
- **上下文压缩感知**：捕获 `contextCompaction` 投影项以及 `context_compaction_finished` 事件，生成 `compaction` 类型的结构化块；
- **视觉呈现**：在 `MessageItem.jsx` 中渲染精美的琥珀色上下文压缩指示条，向用户明确展示大上下文已被系统优雅修剪压缩。

### 2.4 决策 4：多线程工作流设置与目标路由健全
- 网关端点 `/api/workflows/settings`、`/api/workflows/goal` 全面支持可选的 `thread_id` 字段；
- 前端 `api.js` 支持传参，使多线程会话具备精确的针对性控制能力。

### 2.5 决策 5：模型结算错误回读与重入清理保障
- **错误诊断回读**：TUI 在收到 `run_failed` 事件后，主动异步读取已结算的 `turn/read(failed_turn_id).error`，截断展示原始 Provider 故障信息（如 503 错误），杜绝无声丢弃；
- **重入安全性**：在自动化脚本与测试生命周期（setup/teardown）中强制执行 `clear_goal` 与活动轮次检查，保证测试与演示脚本可幂等重复执行。
