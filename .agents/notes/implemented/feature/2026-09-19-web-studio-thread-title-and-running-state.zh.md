# Web Studio 会话标题与运行状态显示

## 结论

Web Studio 将会话列表的主要问题收敛为两个问题：用户正在处理什么，以及哪些会话的
Turn 正在运行。

## 会话标题

- 新会话首次提交非空用户输入后，自动使用输入正文的前 32 个字符作为标题。
- 标题生成前会移除已识别的 Skill 和 Workflow 指令，并压缩连续空白。
- 超过长度限制时，标题末尾添加省略号。
- 手动设置的标题不会被自动标题覆盖。
- 历史会话从 SessionStore 事件中读取第一条用户输入，不再使用最后一轮的 `last_prompt`
  覆盖标题。
- 会话列表和会话详情使用同一个历史标题投影，因此已有多个 Turn 的会话也保持一致。

## 侧栏状态

- 只有 `turn_active=true` 的会话显示“运行中”。
- 空闲会话不显示“已完成”“待命”“已中断”或其他历史状态标签。
- `process_online`、Session 锁和上一轮结算结果仍由运行详情和诊断接口保留，但不占用会话列表的主要阅读位置。
- 选中态使用行背景表示，不再额外显示容易与运行状态混淆的小圆点。
- 多个 Project 或 Thread 同时运行时，各自独立显示“运行中”。切换会话不会停止其他会话。

## 实现边界

标题生成逻辑分别位于前端和 Session catalog。前端负责新输入后的即时反馈，Session catalog
负责历史会话的稳定投影。两者使用相同的长度和空白归一化规则。

侧栏只消费 `turn_active`。运行详情继续消费完整的 Session、Turn、锁和错误状态，因此
该调整不会删除恢复、失败或只读会话所需的诊断信息。

## 验证

- 前端 Node 单测、Vitest UI 测试、ESLint 和生产构建通过。
- Session catalog 覆盖已有多个 Turn 时使用第一条用户输入的回归测试。
- 侧栏覆盖空闲会话不显示历史标签、活跃会话只显示“运行中”的 UI 测试。
