# WebStudio 统一加号入口、文件路径引用与 Goal/Plan 延迟激活

日期：2026-09-17

## 决策

输入框的 `+` 菜单只保留一个 `文件` 入口。文件选择器处理普通文件和图片；
文件夹不提供专用选择器，用户可以从桌面复制或拖入。若桌面桥接能够提供物理
路径，WebStudio 记录路径引用，不复制文件夹，不展开目录，也不保存相对路径树。
浏览器只有目录条目而没有物理路径时，明确提示用户使用路径桥接窗口。

物理路径与普通文件内容是两种附件形态：

- 有路径时，Gateway 只校验并记录 read-only path reference；
- 没有路径时，文件以有界内容附件写入 Gateway 的 Project/Thread 隔离目录；
- 图片仍然通过现有图片输入链路传递；
- `.git` 路径被拒绝；读取不会自动执行脚本，写入和执行仍经过 Host 审批与沙箱；
- 当前消息和队列保留有限附件摘要，历史投影剥离物理路径，仅保留安全名称和数量。

`目标` 和 `计划模式` 也是加号菜单中的编辑器标记，而不是点击即生效的 runtime
控制操作。用户选择后只显示 chip；提交时才把 directive 与 prompt、Skill、文件和
路径附件一起发送。正在执行时整个 payload 进入队列，出队时才设置 Goal 或开启
Plan Mode。这样可以保证用户看到的任务内容与后续执行模式一致。

## 边界

前端不扫描本地文件系统，也不把文件夹递归展开。物理路径仅由桌面桥接、操作系统
拖放数据或文件对象路径属性提供；普通浏览器无法提供时不猜测路径。Gateway 是
路径和内容附件的最终校验边界，Mini Agent 仍负责运行时工具的实际读取授权。

本次不增加目录资源权限模型、不自动执行 Skill 或附件中的脚本、不把附件内容注入
全局系统提示词，也不改变已有 `@` 工作区文件引用和 `$` Skill 激活语义。

## 验证证据

- 前端单元测试覆盖文件选择、文件夹路径拖入、Goal chip 和 popup 外部点击关闭；
- Gateway 测试覆盖路径保留、内容隔离写入、缺失路径和 `.git` 拒绝；
- 普通短文本粘贴仍进入输入框，长日志仍使用独立的临时文本附件。
