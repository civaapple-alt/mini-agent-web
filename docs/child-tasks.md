# 代理子任务

委派任务由父 Session 管理。每个父 Turn 的委派任务在消息流第一次出现的位置汇总为一张
批次卡，批内任务各自显示名称、执行模式、生命周期和最近的有界进展报告。

## 消息流与状态

任务状态来自 App Server 持久化的 Session operation。Gateway 的
`child_operation_updated` 事件用于及时刷新投影，不是另一份状态账本。刷新或重新打开父会话后，
消息流和运行详情会从同一份 operation/report 投影恢复状态。

子代理可用 `task_report` 报告有界进展。父代理通过带游标的 `task_read` 读取报告，并可用
`task_control` 编辑或取消排队任务、引导或取消运行任务、重试失败任务、取消顺序组；需要新增方向时
继续使用 `delegate_task`。完整工具活动和 transcript 留在各自子 Session，不复制到父消息流。

默认最多同时运行 2 个子任务，项目设置可调整为 1–8 个。超出并发槽位的任务会先创建并持久化为
“排队中”，有任务结束后自动启动；任务提示可以包含普通换行和制表符，单条提示仍限制为 32 KiB。
父代理可对每个任务读取一次状态，再优先跟踪运行中的子任务。排队任务会自动等待空位，不需要反复查询。

报告和终态会合并为父会话的待处理唤醒。父 Turn 运行时，父代理在安全续行边界处理；
父代理空闲时，Gateway 可自动启动一轮续行。Gateway 重启不会重放尚未送达的待处理唤醒，
但报告仍留在子 Session，父代理可以在后续 Turn 读取。

## 运行详情与会话入口

“运行详情”的“子任务”列表显示父会话的全部子任务，包括排队、运行、完成、失败和取消项。
存在对应子 Session 时，“打开”会在运行详情右侧抽屉中显示只读消息流，不切换主会话。
运行中的子 Session 每 3 秒刷新一次最近活动；活动列表按 128 项分页，可向前加载。子会话内容
按子任务投影中的 `project_id` 读取；旧投影缺少该字段时使用父会话的项目身份。创建 Session 前失败的任务
仍显示为失败项，但没有无效的打开入口。

项目侧栏隐藏委派子 Session，避免子任务挤占普通会话列表。Session 历史和直接导航仍然保留；普通用户派生的会话继续显示在项目列表中。

子 Session 继承父 Session 的规范 Project。Gateway 创建 fork、写入项目元数据、创建子客户端和绑定客户端时，
都使用同一个 project-qualified `(project_id, thread_id)`。对于 `default` 这类跨项目同名 Thread，
未限定的兼容客户端映射不能决定子任务归属。Gateway 启动恢复时会按父项目重连活动任务并排空持久化队列。

## 排查

若消息流与运行详情暂时不一致，刷新父会话和“运行详情”中的“子任务”列表。没有“打开”入口
通常表示 Child Session 尚未创建，请检查失败项的诊断信息。Gateway 重启后仍能读取已持久化报告；
没有自动唤醒时，可在后续 Turn 让父代理调用 `task_read`。

如果子任务出现在错误的项目下，先核对子 Session 的 `parent_session_id` 和 `path`。它们应分别指向当前父 Session，
以及父项目对应的 Session 目录。更新 Gateway 后重启服务以加载修正后的项目元数据和恢复队列；不要把子 Session
日志文件手工移动到另一个项目目录。
