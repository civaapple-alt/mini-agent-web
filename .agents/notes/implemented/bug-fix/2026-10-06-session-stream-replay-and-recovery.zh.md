# 会话流实时、重放与恢复的一致性

状态：implemented；日期：2026-10-06；范围：Web Studio 消息流、重放和恢复 UI

## 决策

消息流在实时、历史重放和重启恢复时保留相同的执行段边界。助手思考与工具活动按原有顺序分组，回放时恢复持久化耗时，不把缺失耗时显示成“不足 1 秒”。“已处理”时长与第一个活动块之间保留间距。这避免一次长运行在恢复后变成大量相同的小卡片或一段压缩文本。

默认视图只显示工具摘要。用户点击“查看详情”后才看参数和输出，避免鼠标经过会话流时不断弹出大块内容。推荐的问题选项不会被预选；TTFT 与响应时间放在对应用户问题下方。图片和粘贴的大段文本可分别打开预览，图片尺寸限制在视口内。

App Server 重启后的未结 Turn 通过 `turn/read` 活动投影恢复到主会话流。若工具调用结果仍不确定，Studio 显示对应核对活动和有界、脱敏后的参数。记录结果仍需用户确认，查看活动不会自动继续 Turn。

Steer 请求使用客户端请求 ID 关联原消息。超过等待时限只显示“结果未确认”，不直接当作拒绝，也不暗示可以安全重发；收到运行时确认后再更新同一条消息。重连时，Studio 等待历史、运行状态、审批和事件回放完成核对后才恢复操作。只有权威快照确认空闲时才清除过期的“停止中”状态，待核对工具结果继续保留。

## 所有权

ThreadItems 是已结算历史的首选投影。App Server 检查点补充未结 Turn 的有界活动；Web Studio 合并和呈现，不把自己的重放缓存升级为执行事实。工具是否成功以核对和 App Server 结果为准。
